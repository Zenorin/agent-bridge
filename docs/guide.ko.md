# agent-bridge 사용 설명서

[English](guide.md)

처음 쓰는 분을 위한 안내예요. 명령과 옵션의 전체 목록은 [reference.ko.md](reference.ko.md)에 있어요.

## 1. agent-bridge가 하는 일

AI 코딩 도구는 각자 따로 열어서 써야 해요. agent-bridge는 그 사이에 **작업함**을 하나 두고, 도구끼리 일을 주고받게 해 줘요.

```
작업 적기 ─▶ [작업함] ─▶ 받는 AI가 실행 ─▶ 결과(회신) ─▶ 확인(ACK)
```

- **작업**: "이 폴더를 읽고 요약해 줘"처럼 누군가에게 맡기는 일 하나예요. JSON 파일(봉투)로 적어요.
- **실행기**: 작업함에서 작업을 꺼내 해당 AI를 실제로 실행하는 부분이에요. 실행기를 켜 둬야 작업이 진행돼요.
- **회신**: AI가 돌려준 결과나 질문이에요.
- **확인(ACK)**: 회신을 잘 받았다고 알리는 것이에요. 확인하기 전에는 같은 회신이 다시 전달돼요.

작업함 자체는 AI를 부르지 않아요. **실행기가 작업을 실행할 때만** 각 AI의 사용량이 들어요.

## 2. 시작하기 전에

1. 쓸 AI(Codex, Claude Code, Antigravity `agy`)를 **직접 설치하고 직접 로그인**해 두세요. agent-bridge는 대신 로그인하지 않고, 로그인 정보를 받거나 저장하지 않아요. 각 서비스의 약관을 지킬 책임은 사용하는 분께 있어요.
2. AI는 하나만 있어도 쓸 수 있어요. 둘 이상이면 서로 일을 주고받을 수 있어요.
3. 압축을 푼 폴더에서 `Self Test.cmd`를 한 번 실행해 설치 상태를 점검하세요(AI를 부르지 않아요).

```powershell
.\agent-bridge.cmd doctor          # 어떤 AI를 찾았는지 보기
.\agent-bridge.cmd settings        # 쓸 AI와 Gemini 연결 방식 보기
```

## 3. 켜는 방법 세 가지

| 방법 | 언제 쓰나요 |
|---|---|
| **`Start Tray.cmd`** | 가장 편해요. 오른쪽 아래 알림 영역에 아이콘이 생기고, 창은 뜨지 않아요 |
| `Start Dashboard.cmd` | 검은 창을 열어 둔 채로 대시보드를 쓰고 싶을 때 |
| `agent-bridge.cmd` 명령 | 작업을 파일로 보내고 결과를 명령으로 받고 싶을 때 |

### 오른쪽 아래 트레이 아이콘

`Start Tray.cmd`를 실행하면 파란 동그라미 아이콘이 생겨요(숨겨진 아이콘 화살표 안에 있을 수 있어요). 아이콘을 **오른쪽 클릭**하면:

- **실행기 시작 / 중지**: 지금 상태가 맨 위에 보여요
- **대시보드 열기**: 아이콘을 두 번 눌러도 돼요
- **설정 열기**: 대시보드의 설정 탭으로 바로 가요
- **종료**: 대시보드와 아이콘을 함께 꺼요

작업 폴더는 사용자 폴더예요. 다른 폴더나 Git 저장소를 쓰려면 아래처럼 직접 실행하세요. 트레이로 켠 실행기는 **읽기 전용**이에요. 파일 쓰기가 필요하면 `--allow-write`를 붙여요.

```powershell
.\agent-bridge.cmd serve --repo "C:\work\project" --tray --allow-write
```

## 4. 대시보드 사용법

실행하면 `http://127.0.0.1:숫자` 주소로 열려요. 이 주소는 **내 컴퓨터 안에서만** 열려요.

| 탭 | 하는 일 |
|---|---|
| 작업 | 새 작업을 만들고, 진행 상황과 결과를 봐요 |
| 작업 폴더 | Git 저장소에서 별도 작업 폴더(worktree)를 만들어요. 여러 작업이 서로 파일을 건드리지 않게 할 때 써요 |
| 프로필 | 작업마다 AI에게 넘기는 정보와 설정을 봐요 |
| 설정 | 쓸 AI를 켜고 끄고, Gemini 연결 방식을 골라요 |

### 작업 상태

| 상태 | 뜻 | 할 일 |
|---|---|---|
| 대기 중 | 작업함에서 차례를 기다려요 | 실행기를 시작했는지 확인해요 |
| 작업 중 | AI가 하고 있어요 | 기다려요. 필요하면 취소해요 |
| 준비됨 | 결과가 도착했어요 | 결과를 읽고 **수신 확인**을 눌러요 |
| 진행 불가 | 멈췄어요 | 이유를 읽고 아래 "문제 해결"을 보세요 |
| 취소됨 | 취소했어요 | |

## 5. 설정: 쓸 AI와 Gemini 연결 방식

**쓸 AI**: 켜 둔 AI끼리만 일을 주고받아요. 꺼 둔 AI에게는 작업을 보낼 수 없어요. 실행기가 켜져 있으면 껐다 켜야 바뀐 설정이 적용돼요.

**Gemini 연결 방식**: 고르기 전에는 Gemini가 작업을 받지 않아요.

- **Gemini API 키 (권장)**
  1. [Google AI Studio](https://aistudio.google.com/apikey)에서 API 키를 만들어요.
  2. Windows의 **사용자 환경 변수**에 이름 `GEMINI_API_KEY`, 값은 만든 키로 추가해요.
  3. 트레이와 터미널을 모두 닫았다가 다시 열어요.
  4. 설정 탭에서 "Gemini API 키"를 고르고 저장해요.

  사용한 만큼 Google에 요금이 나갈 수 있어요. agent-bridge는 키를 저장하거나 화면에 보여 주지 않아요.
- **개인 Google 계정**: 약관 위반이 될 수 있어요. [Google의 안내](https://antigravity.google/docs/faq/)는 다른 프로그램이 Antigravity 로그인을 이용하는 것을 금지하고, 계정이 정지될 수 있다고 해요. 위험 안내에 동의해야만 고를 수 있어요.
- **둘 다**: 평소에는 기본 방식을 쓰고, 작업마다 `"gemini_auth": "api-key"` 또는 `"account"`로 바꿀 수 있어요.

## 6. 해 보기: 상황별 예제

작업 봉투(`task.json`)의 기본 모양이에요. `sender`는 보내는 쪽, `recipient`는 맡을 AI예요. 둘은 달라야 해요.

```json
{
  "message_id": "hello-1",
  "task_id": "hello",
  "sender": "claude-code",
  "recipient": "codex",
  "cwd": "C:/work/project",
  "goal": "이 폴더를 읽고 짧게 요약해 줘",
  "acceptance": ["파일을 수정하지 않고 근거와 함께 요약"],
  "sandbox": "read-only",
  "write_files": [],
  "file_refs": []
}
```

- `message_id`: 이 작업의 고유 이름이에요. **같은 이름으로 같은 내용을 다시 보내면 새 작업이 생기지 않아요.**
- `acceptance`: 완료 조건이에요. AI가 조건마다 통과 여부와 근거를 적어서 돌려줘요.

### 예제 A. 읽기만 시키기

위 봉투 그대로 쓰면 돼요. 보내고, 한 번 실행하고, 결과를 받아요.

```powershell
.\agent-bridge.cmd send .\task.json
.\agent-bridge.cmd run --once
.\agent-bridge.cmd receive --as claude-code
.\agent-bridge.cmd ack "<받은 회신의 message_id>" --as claude-code
```

`run --once`는 맡을 작업이 없으면 끝나요. `--once`를 빼면 계속 기다려요.

### 예제 B. 파일 쓰기 허용하기

쓰기는 **세 가지가 모두** 있어야 돼요. 하나라도 없으면 실행되지 않아요.

1. 봉투에 `"sandbox": "workspace-write"`
2. 봉투의 `write_files`에 고칠 파일을 적기 (예: `["README.md"]`)
3. 실행기를 `--allow-write`로 켜기

```powershell
.\agent-bridge.cmd run --once --allow-write
```

목록에 없는 파일이 바뀐 것을 발견하면 작업을 `진행 불가`로 멈추고 확인을 기다려요. **미리 막는 장치가 아니라 사후 감지**라서, 이미 바뀐 내용을 되돌리지는 않아요. 중요한 폴더는 Git으로 관리하고, 작업 폴더(worktree)를 따로 만들어 쓰는 걸 권해요.

### 예제 C. 한 AI가 쓰고 다른 AI가 검토하기

봉투에 `"chain": {"review": true}`를 넣으면 Codex가 만든 결과를 Claude Code가 독립적으로 검수해요. **Codex와 Claude Code가 모두 켜져 있어야** 해요. 검수에서 반려되면 지적 사항을 담은 재작업 작업이 만들어져요.

### 예제 D. 작업 중 AI가 질문할 때

AI가 정보가 모자라면 추측하지 않고 `질문` 상태로 멈춰요. 대시보드의 작업 상세에서 답변을 적으면 같은 대화로 이어서 진행돼요. 명령으로는 질문 회신의 `reply_id`를 지정해 후속 작업을 보내요(`send followup.json --reply-to <reply_id>`).

### 예제 E. 작업마다 모델과 effort 고르기

봉투에 `"model"`(모델 이름)과 `"effort"`(`low`·`medium`·`high`·`xhigh`)를 넣어요. 가벼운 일은 낮은 effort로 하면 사용량이 줄어요.

## 7. 사용량과 비용

- 작업함, 대시보드, 트레이 자체는 AI를 부르지 않아요.
- 실행기가 작업을 실행할 때 **각 AI 서비스의 요금제나 API 요금**으로 사용량이 들어요.
- 시도마다 입력·출력 토큰이 기록돼서 대시보드 작업 상세의 "사용량"에서 볼 수 있어요.
- `check-connections`는 설치된 AI마다 짧은 실제 호출을 한 번씩 해요. 사용량이 조금 들어요.
- 같은 AI가 입력으로 읽는 기본 지침이 있어서, 답이 짧아도 입력 토큰은 생겨요.

## 8. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 작업이 계속 `대기 중`이에요 | 실행기가 꺼져 있어요. 트레이에서 "실행기 시작"을 누르거나 `run`을 실행하세요 |
| "Gemini 연결 방식을 아직 고르지 않았어요" | 설정 탭이나 `settings --gemini-auth api-key`로 방식을 고르세요 |
| "GEMINI_API_KEY 환경변수가 없어요" | 사용자 환경 변수에 키를 넣은 뒤 트레이·터미널을 **닫았다가 다시** 여세요 |
| "개인 Google 계정 방식은 … 동의한 뒤에만" | 위험 안내를 읽고 동의하거나 API 키 방식을 고르세요 |
| "로그인이 필요하거나 인증에 실패했어요" | 해당 AI 도구를 직접 열어 로그인한 뒤 다시 시도하세요. 상태는 `check-connections`로 확인해요 |
| "사용 한도에 도달했어요" | 해당 서비스의 한도가 찼어요. 시간이 지난 뒤 `다시 대기열에 넣기`를 누르세요 |
| `진행 불가`: 범위 밖 파일 변경 | 목록에 없는 파일이 바뀌었어요. 변경 내용을 확인하고, 필요하면 되돌린 뒤 다시 대기열에 넣으세요 |
| `진행 불가`: 질문 | AI가 묻고 있어요. 답변을 적어 보내세요 |
| "이 PC에서 사용할 수 없는 에이전트" | AI를 찾지 못했거나 설정에서 꺼 뒀어요. `doctor`와 설정을 확인하세요 |
| 트레이 아이콘이 안 보여요 | 알림 영역의 숨겨진 아이콘(위 화살표) 안을 보세요. "이미 실행 중"이라고 나오면 이미 켜진 아이콘이 있는 거예요 |
| Windows가 경고를 띄워요 | 스크립트에 코드 서명이 없어서예요. Release 페이지의 SHA-256 값과 맞는지 확인한 뒤 `Unblock-File`로 차단을 풀어요 |
| 대시보드에서 작업을 못 만들어요 | 대시보드의 작업 등록에는 Git과 Git 저장소가 필요해요. 일반 폴더는 명령(`send`)으로 보내세요 |

## 9. 자주 묻는 질문

**내 파일이나 대화가 어딘가로 전송되나요?**
agent-bridge는 자체 서버로 아무것도 보내지 않아요. 사용 통계도 없어요. 작업 내용은 내 컴퓨터의 작업함에 저장되고, AI에게 가는 내용은 각 도구가 해당 서비스로 보내는 것이에요.

**API 키나 비밀번호를 저장하나요?**
아니요. 설정 파일에는 실행 파일 경로와 선택한 방식만 적혀요. 키는 사용자 환경 변수에만 있어요.

**AI를 하나만 써도 되나요?**
네. 보내는 쪽(`sender`)은 결과를 받을 이름일 뿐이라, 그 AI가 설치되어 있지 않아도 돼요.

**macOS나 Linux에서도 되나요?**
아직 Windows x64만 확인했어요. 트레이 아이콘도 Windows 전용이에요.

**Claude Code, Codex, Antigravity와 관계가 있나요?**
없어요. agent-bridge는 개인이 만든 독립 프로젝트이고, 각 회사의 공식 도구가 아니에요.

**문제가 있거나 바라는 기능이 있어요.**
[GitHub Issues](https://github.com/Zenorin/agent-bridge/issues)에 남겨 주세요.
